1 · Graph basics

A graph is:

  • Vertices (nodes) — things we care about
  • Edges — relationships between pairs of vertices

We write G = (V, E): vertex set V, edge set E.

Kinds of graphs

  • Undirected — edge {A,B}: travel both ways
  • Directed — edge A → B: one direction only
  • Weighted — each edge has a cost / length / time

The same C representation idea extends: unweighted lists → add a weight field when needed.

2 · Storing a graph in C

From your consolidated guide: C has no built-in map { id: [neighbors] }.

Adjacency list — one linked list per vertex: only store neighbors that exist (good for sparse graphs).

Core struct (unweighted)

struct Node {
    int vertex;
    struct Node* next;
};

struct Node* adj[MAXV];  /* adj[i] = head of list of neighbors of i */

Picture: adj[0] → 1 → 2 → NULL, adj[1] → 0 → NULL for an undirected edge 0–1 and 0–2.

addEdge — undirected

void addEdge(struct Node* adj[], int src, int dest) {
    struct Node* newNode = createNode(dest);
    newNode->next = adj[src];
    adj[src] = newNode;

    newNode = createNode(src);
    newNode->next = adj[dest];
    adj[dest] = newNode;
}
  • Insert at head: newNode->next = adj[src]; adj[src] = newNode; — O(1)
  • Two insertions because the edge works both ways

Directed & weighted variants

  • Directed: only insert on adj[src] (one list update)
  • Weighted: add int weight; to the struct; Dijkstra / Prim / Kruskal all consume weights from lists or edge arrays

3 · Why traversals first?

Almost every graph algorithm is either:

  • a controlled DFS / BFS, or
  • a greedy loop that picks “best” edges/vertices using ideas similar to BFS layers or DFS order

DFS (depth-first)

  • Go deep, then backtrack — stack / recursion
  • Useful: connectivity, path existence, cycle detection, topological sort (on DAGs)

BFS (breadth-first)

  • Expand in “waves” — queue (FIFO)
  • Unweighted shortest path: first time you reach a node is along a shortest route (in edge count)

Weighted shortest paths need more than raw BFS — that leads to Dijkstra.

4 · Shortest paths

SettingTypical algorithm
UnweightedBFS from source
Non-negative weightsDijkstra
General weights (no neg cycles)Bellman–Ford

Dijkstra’s algorithm weighted · non-negative

Maintain tentative dist[v] from source. Repeatedly:

  1. Pick unsettled u with minimum dist[u]
  2. Finalize u (why safe? no negative edges)
  3. Relax: dist[v] = min(dist[v], dist[u] + w(u,v)) for neighbors v

Naive pick-min is O(V²); a min-heap gives roughly O(E log V) for sparse graphs.

5 · Prerequisite: DAG

Directed acyclic graph — directed, and no directed cycles.

Models dependencies: task B after A, course Y after X, build steps.

If there is a cycle, you cannot order all tasks consistently → no topological ordering.

Topological sort

A linear ordering of vertices such that every edge u → v has u before v.

Idea (DFS): run DFS; push vertex onto a stack when you’re “done” with it; reverse stack (or output finish times descending).

Idea (Kahn / BFS): start with indegree 0; repeatedly remove a vertex, decrement indegrees of successors.

Representation note

Use the same adjacency list for outgoing edges; maintain an indegree[] array for Kahn. Your struct Node pattern still applies — only the interpretation (directed vs undirected) changes.

6 · Minimum spanning tree (MST)

Spanning tree: connected, no cycles, includes all vertices.

MST: among spanning trees, one with minimum total edge weight.

Classic setting: undirected, connected, weighted graph.

Prim’s algorithm

  • Start from any root vertex
  • Grow a tree: repeatedly add the cheapest edge that connects the tree to a new vertex
  • Implementation: track min cost to attach each fringe vertex (priority queue)

Feels like Dijkstra, but key is minimum edge cost to the growing tree, not distance from a single source.

Kruskal’s algorithm

  • Sort all edges by weight ascending
  • Scan edges; add an edge if it connects two different components (no cycle)
  • Union–find (DSU) tracks components efficiently

Prim vs Kruskal

PrimKruskal
ViewGrows one tree from a rootMerges components via global cheapest edges
Best whenDense graphs, adjacency-friendlySparse graphs, edge list + sort

7 · Application: traffic & redirection

Road network ≈ weighted graph: weights = time, distance, or congestion score.

  • Shortest / fastest route: Dijkstra (or A* with a heuristic) from source to destination
  • Redirection / closure: remove or raise weight on blocked edges; re-run routing; multi-source variants for “distance to nearest hospital”
  • MST: connect all junctions with minimum cable/road cost (design), not the same as pairwise shortest paths

8 · Application: traveling salesman (TSP)

Problem: visit every city once, return to start, minimize total tour length.

TSP is NP-hard — unlike MST or Dijkstra, no known polynomial-time algorithm that solves every instance optimally.

  • MST is a lower-bound building block in some approximations, not the tour itself
  • Practical tools: heuristics (nearest neighbor, 2-opt), integer programming, branch-and-bound

Lesson: same graph model — vastly different difficulty depending on the question.
